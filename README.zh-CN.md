# Paperroom

[English](README.md) · 中文

Paperroom 帮助论文作者在 Codex、Claude Code 或 Claude 桌面版的原对话里主导写作。你可以随时讨论研究问题、补充实验、调整论证。准备让 AI 写正文时，打开本地写作间，亲手写下这一段要怎样带着读者理解研究。AI 根据你的句意逐段起草，整节完成后由你对照排版审稿。

## 安装

| 场景 | 安装方式 |
| --- | --- |
| Claude 桌面版 Chat，macOS | 下载 [Paperroom.mcpb](packages/Paperroom.mcpb)。在 Settings → Desktop app → Extensions → Manage → Advanced settings → Install Extension 中选择文件。安装后在聊天输入框旁的 ＋ → Connectors 查看 Paperroom。 |
| Claude Code，自动更新 | 下载 [Enable-Claude-Updates.command](Enable-Claude-Updates.command) 后在 macOS 运行。也可以在解压的插件包里双击同名文件。 |
| Claude Code 或 Codex | 下载并完整解压 [Paperroom-Plugin-0.6.12.zip](packages/Paperroom-Plugin-0.6.12.zip)。在 macOS 双击 `Install-Paperroom.command`，或在解压目录运行 `python3 install.py`。使用源码时也可以直接从仓库根目录运行安装器。 |

Paperroom 需要本机 Python 3.9 或以上版本，使用你原对话中的模型。使用 Claude Code（含 VS Code 扩展）或 Codex 时，可以在解压目录里运行 `python3 install.py --client claude` 或 `python3 install.py --client codex`，只安装到相应客户端。重新打开客户端后，在论文对话里说 **「请调用 Paperroom 的 `get_usage()` 工具，告诉我当前安装的版本。」** 工具会同时返回版本号和对应的使用说明。

**已装旧版的 Claude Code 用户**也只需运行一次 [Enable-Claude-Updates.command](Enable-Claude-Updates.command)。它把用户级的 Paperroom 更新源切换到本项目的 GitHub 分支 `v2-author-workspace`，安装该分支上的新版，并开启 Claude Code 自带的自动更新。私有仓库需要本机 Git 已有读取权限。成功后可重新打开本地 Claude Code 会话，或在本地 Claude Code 交互终端输入 `/reload-plugins`。桌面版的聊天气泡使用单独的 Paperroom 桌面扩展，可在该对话的 ＋ → Connectors 中查看。以后作者在该分支发布新版本时，Claude Code 会在启动会话后后台检查。可在 `/plugin` 的 **Marketplaces → paperroom-local** 中管理这个开关。

使用离线安装方式时，每次升级可运行新包内的 `Install-Paperroom.command`。升级 Claude 桌面版 Chat 的扩展时，在扩展管理页选择新版 [Paperroom.mcpb](packages/Paperroom.mcpb)，完成后回到原对话的 ＋ → Connectors 查看 Paperroom。已有单节任务仍可通过 `writing_status` 查看或用原来的任务 ID 继续。第二版的三级大纲在同一论文项目中独立开始记录。

## 第一次使用：用已有初稿重写引言

1. **在原聊天里讨论。** 让客户端可以访问存放初稿和实验结果的论文目录。例如：「用 Paperroom 处理 `/path/to/my-paper`。先读初稿和实验，讨论这些证据能回答什么研究问题。」达成共识后，让 AI 记录研究问题和证据，并提出章节安排。
2. **在浏览器写作间规划段落。** 采用或修改章节安排，打开 Introduction，亲手写下每段要让读者理解什么，点「保存段落大纲」。今天只写引言，就只展开这一节。
3. **选一段安排句意。** 想看建议时，在原聊天说「把 Introduction 第 1 段的逐句参考放到参考栏」。在写作间键入自己的逐句意图，点「保存并允许起草本段」。回到聊天说「请按已保存的句意起草 Introduction 第 1 段」。
4. **审阅排版。** 整节各段起草完成后，在聊天里说「发布 Introduction 给我审阅」。在写作间阅读编译后的页面，标出具体位置并提交意见。请 AI 据此修订、发布下一版，再点「章节版本对照」并排查看两版。

下次继续或更换客户端时，选回同一个论文目录。目录中的 `paper.md` 保存大纲，项目数据库保存已提交的进度和审阅记录。升级前先提交旧页面里正在编辑的内容，尤其是从 0.6.2 升级时。随时可以让 AI 调出[插件内置的使用说明](plugins/paperroom/runtime/README-workflow.md)。

## 三级大纲

| 层级 | 谁来写 | 可以参考 | 下一步 |
| --- | --- | --- | --- |
| 整篇有哪些节、每一节的作用 | 和 AI 讨论结构后由 AI 草拟，作者采用或修改 | 研究问题、实验结果概述和可选的整篇大纲 AI 参考 | 任选一节已采用的章节规划段落 |
| 这一节有哪些段、各段怎样衔接 | 作者 | 已定的论文大纲、研究材料和 AI 对本节的参考 | 任选一段安排句意 |
| 这一段的每句话要说什么 | 作者 | 作者的段落计划、相关证据和按段生成的逐句参考 | AI 可以起草这一段 |

章节清单通常很短，所以由 AI 用 `propose_paper_outline` 草拟（已有论文直接取 `\section` 标题）。在写作间读过后点「采用」，或修改后保存；采用后才能展开这一节的段落大纲，时间记录会写明由谁草拟、由谁采用。

规划章节时，可以在已有段落之前插入小标题。用「删除段落」移除一段，保存前可以点「撤销上次删除」。右侧参考栏优先显示 AI 参考，桌面上可以独立翻动。提交段落计划后，聊天中的 AI 可以结合本节参考和你写的段落作用，给出每句话要表达什么、为何接在上一句之后。逐句意图仍由你键入，支持直接混写 LaTeX，例如 `$\Delta = r - p$`。

三个大纲层级都可以在聊天里指定操作。「给整篇大纲生成一份 AI 参考，放到参考栏」会直接生成并保存。「润色并更新 Method 第 2 段的段落作用」会改写该段已保存的文字。「第 3 句的意图可以怎么表达？给我两个选项」只在聊天里讨论。你可以随后指定采用哪一句，也可以继续在工作区手动修改。[给 AI 助手的写作流程](plugins/paperroom/runtime/README-workflow.md)

进入小黑屋填写段落大纲、逐句意图或审阅意见时，请亲自键入。作者输入区会拦截复制、剪切、粘贴和拖放文字。研究问题和实验材料仍可正常粘贴。

句意用自己熟悉的语言写即可。可以把论证写到“先解释这个观察，再说明它支撑什么，最后指出比较没有覆盖的条件”。写完这一层就回到原聊天让 AI 继续。其余的段落和章节可以稍后再规划。

## 审阅成稿

整节各段准备好后，从原聊天请求编译并打开该版的论文节选。作者在浏览器里对照大纲阅读版面，将修改意见或保留理由落在具体位置。提交足够的意见后，把已审阅的版本交回 AI。再次发布会产生新版本，可对照标出的变化和旧版反馈复查。

## 查看准备好的图片和表格

在原聊天里告诉 AI 用哪些数据、图或表要表达什么，让它生成或修改后存入对应目录。路径从论文项目根目录算起。首次保存时，AI 可以用聊天客户端的文件工具创建目录。你也可以自己把准备好的文件放进去。

| 内容 | 目录 | 支持格式 |
| --- | --- | --- |
| 图片 | `paperroom-assets/figures/` | PNG、JPEG、WebP、PDF |
| 表格 | `paperroom-assets/tables/` | LaTeX 编译的 PDF |

> 根据刚才讨论的结果更新基准实验表，编译成 PDF。编译成功后保存为 `paperroom-assets/tables/Method/benchmark.pdf`，再打开 Paperroom 给我看。

在写作间顶部打开「图片与表格」。两个页签分别显示已准备好的成品，也能查看 `Method/` 等子目录。在聊天里说明要改什么，让 AI 更新同名文件，再点「更新图表列表」即可看到修改结果。要看图表在某次发布时的实际排版，可以打开相应章节的对照。

## 多轮修改

作者提交一版的审阅后，AI 发布下一版时必须对每条意见逐条回应：已修改、保留原文，或有不同意见，并写明理由。漏回应或重复回应都会被拒绝。作者打开新版时，「上一版意见的处理」默认展开，每条意见旁边就是 AI 的回应。页面还会提示本版改了哪几段，其余段落可以略读。

第一版默认至少写 3 条意见；从第二版起默认至少 1 条。作者觉得这一版已经可以时，可以选「本版通过，无新意见」，不必凑条数；已经写下的意见会一并提交。

## 正文以论文的 LaTeX 源码为准

Paperroom 直接读取论文的主 `.tex`，包括其中 `\input`、`\include` 的章节文件。大纲里的每一节对应源码中同名的 `\section`，各段按空行分隔，按顺序对应作者的段落大纲。图、表和注释不算正文，行间公式归入所在段落。AI 把段落写进源码后再登记，不需要另存一份正文。

小改动不设门槛，比如改词、调句、改引用或公式。Claude Code 和 Codex 插件自带一个编辑前检查：AI 修改 `.tex` 时，如果会新增一段或把一段改写超过一半，而作者还没写这一段的逐句意图，这次修改会被拒绝，并告诉 AI 是哪一段、去哪里补大纲。多次小改会累计计算，拆成小步也绕不过去。作者自己手写的段落，AI 仍可小幅润色。AI 不能直接编辑保存大纲的 `paper.md`。通过 shell 命令写文件无法事先拦截，命令执行后会被检出，并要求 AI 撤回。Codex 首次使用时需要在 `/hooks` 中批准一次 Paperroom 的检查；Claude 桌面版的聊天不直接改文件，不涉及这项检查。只有新增一段，或者把一段改写超过一半时，才需要作者先写好这一段的逐句意图。很短的新增（少于约 20 个英文单词或 40 个汉字）不受限制。发布时，登记后的小改动会自动采纳；某一段在登记后被改写超过一半，或源码段数和大纲段数不一致，都会被拦下并指出位置。

发布和保存原稿时，Paperroom 在临时目录编译论文，按章节标题到下一节之间的位置自动选出物理页码，不在论文目录里写入任何文件。罗马数字前言、`\include` 带来的换页都按 PDF 的实际页数计算。主 `.tex` 不止一个，或者大纲里的章节名和源码标题不同时，AI 可以用 `bind_section_source` 指定主文件和 `\label`。没有 LaTeX 主文件的项目沿用原来的方式，正文随草稿一起登记。

旧项目无需手动迁移。已发布的版本和审阅记录保持不变，数据库里的草稿作为登记快照继续使用。写作间会显示每段在源码中的位置，以及是否需要 AI 重新登记。

## 调出已有章节并对照两版

在左侧目录选中章节，点标题旁的「章节版本对照」，会直接看到最近两次发布的排版。例如 Method 发布第 3 版后，打开就是左边第 2 版、右边第 3 版。首次改稿用发布前保存的原稿作为改前版。只有一份排版时就单独显示。以前的审阅链接仍然打开当时的稿件，方便核对批注。

在整节审阅页，稿件上方的「改前 / 改后」按钮可以原地翻看两版。翻看时停在相近的页面位置，旁栏里写到一半的意见和页上标记保持原样。没有往下读就翻回来时，会回到刚才的位置。手机上的对照窗口占满屏幕，用同一组按钮在两版之间翻看，可选「正文宽」或 2 倍放大来阅读正文。

如果已有初稿，可在该节的「章节版本对照」中导入 PDF，或选择可独立编译的 TeX 文件。使用论文项目内的文件路径。如果 PDF 包含整篇论文，可以指定本节页码，例如 `2-4`。也可以在原来的 Claude Chat 里这样请求。

> 用 Paperroom 的 `import_section_reference` 把项目里已编译的 `main.pdf` 第 2 至 4 页存为 Introduction 的「原稿」。

写大纲和安排句意时，也可以从章节页打开对照。较早版本仅保存页图时，仍可从已有审阅链接查阅这些页图。

渲染可以使用独立编译的 LaTeX 节选，也可以使用按论文原模板生成的匹配 PDF 和页码范围。多文件论文可直接用主 `.tex` 和本节页码，Paperroom 会读取其中 `\input`、`\include` 的章节文件，改前和改后因此使用同一套模板排版。由 AI 另行提供 PDF 和页码时，Paperroom 会从最终 PDF 节选提取文字，依次核对已登记的段落；直接从源码发布时，正文和页码都来自同一次编译，不需要这项核对，含公式、图表引用和自定义命令的段落也能正常发布。漏页或文字无法核实时会指出段号，保留草稿供重试。复杂公式、自定义宏或扫描件可能需要改用文字可核对的排版。如果 AI 修改源文件前项目里已有同名章节、却还没保存改前排版，`workspace_status` 和保存段落草稿的结果会提示先保存原稿。编译 `.tex` 需要 Tectonic 或 pdfLaTeX，也会使用 ChatGPT 桌面版自带的 Tectonic。生成页图优先使用 Poppler 的 `pdftoppm`，macOS 还可以使用系统 PDFKit。

作者表单及版本记录保存在本机。模型可读取的材料遵循所用客户端的权限和服务设置。Paperroom 的阶段约束适用于它处理的起草和发布请求，宿主聊天仍有直接输出文本的能力。

## 写作时间记录与离线核验

打开写作间右上角的「时间记录」，可以按顺序查看每次提交三级大纲、发布章节版本和提交审阅意见的本机时间。从升级后的下一次提交开始记录，已有稿件不会补记当时的提交时间。默认情况下，记录仅保存在论文项目中，使用时无需云账户或区块链。

如需让审稿人独立核验存在时间，可在 Claude 桌面扩展的「时间戳服务地址（可选）」填入所选 RFC 3161 机构的 HTTPS 服务地址。终端客户端可在启动 Paperroom 的进程环境里设置 `PAPERROOM_TSA_URL`，然后重新启动客户端或写作间。在「时间记录」中选中一次提交并点「申请第三方时间戳」。Paperroom 只向该机构发送该事件的加盐 SHA-256 摘要及协议字段，保存核验过的签名回执。申请和核验回执需要支持 `openssl ts` 的 OpenSSL，机构使用私有 CA 时可用 `PAPERROOM_TSA_CA_FILE` 指向受信任的 PEM 证书。

点击「下载本地核验包」可导出 JSON。**分享前请检查文件**，其中包含大纲、逐句意图、已记录的稿件内容和审阅意见等原文。审稿人可从项目源码或解压后的插件包根目录运行以下命令。

```sh
python3 scripts/verify_timestamps.py paperroom-timestamps.json
# 使用审稿人自行信任的 CA 时
python3 scripts/verify_timestamps.py paperroom-timestamps.json --ca-file trusted-ca.pem
```

脚本离线重算事件摘要、检查顺序，并用核验者的受信任证书验证回执。每份有效回执说明该事件及其前序记录最迟在签发的 UTC 时间已存在。签发时间可能晚于本机提交时间。输出分别列出有效回执数、回执覆盖的事件数以及剩余仅有本机时间的事件数。单份导出只反映所含记录，审稿人无法据此判断是否省略了末尾事件、实际由谁输入或作者投入了多少思考。

## 语言

写作间有中文和英文两种界面，默认跟随浏览器语言，右上角可以随时切换。切换后，Paperroom 发给 AI 的提示和工具报错也会使用同一种语言。逐句意图和审阅意见可以用任何语言写，Paperroom 不会改动作者写的内容。

## 本地体验和开发

在 macOS 解压插件包或下载完整仓库后，可以双击 [Try-Paperroom.command](Try-Paperroom.command)，打开一份可直接批注的虚构论文。每次启动都会创建独立样例，关闭服务后清理本次样例。真实论文请在解压目录或仓库根目录运行以下命令，并传入已有的论文目录。

```sh
python3 plugins/paperroom/runtime/workspace_server.py /absolute/path/to/paper
```

完整的 AI 草拟流程需要在已连接插件的客户端中进行。第一版的 [离线演示](demo/demo.html) 也保留在仓库中，可用浏览器直接打开。

从仓库运行测试，并重新生成两种安装包：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build_packages.py
```

向自动更新用户发布运行时改动时，需要同步递增 Claude Code、Codex 插件清单和 MCP 服务的版本号，再将新版本推送到 `v2-author-workspace`。[Claude Code 插件发布说明](https://code.claude.com/docs/en/plugins/host-marketplace#keep-users-up-to-date)

源码使用 MIT 许可。终端客户端可通过各自的插件管理界面卸载 Paperroom，论文目录内的写作记录由作者保管。
