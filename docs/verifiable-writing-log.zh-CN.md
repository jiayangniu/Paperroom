# Paperroom 可校验写作日志

投稿时，作者可以随论文附带一份写作日志 `paperroom-log.json`。审稿人打开就能顺着时间线看到：作者怎么安排段落、采纳过哪些 AI 建议、审阅稿件时提过什么意见，以及后面怎么改的。哪些原文愿意公开由作者自己勾选，至于参与得深不深，交由读者根据具体记录自行判断。

## 作者怎么导出

1. **平时照常写，按需开启可信时间戳。** 在写作间右上角打开 **时间记录**。如果希望为正式版本留一份第三方时间证明，在这里勾选开启可信时间戳。之后每次保存带 PDF 的版本，Paperroom 会自动把“截至这一版的日志指纹 + 该版 PDF 指纹”发给时间戳机构（机构只收到摘要，看不到论文和笔记）。断网或中途退出也不影响保存稿件，下次打开 **时间记录** 点 **立即补盖时间戳** 即可补盖，回执上显示机构实际签发的时间。
2. **选定投稿版本。** 投稿前点 **导出写作日志**，选择要提交的版本（比如 V2）。导出的日志会包含截至该版保存的历史，以及紧接着针对该版提交的审阅或通过记录；如果想把之后其他版本的活动也带上，选 **全部记录**。
3. **勾选要公开的原文并预览。** 导出文件默认包含项目名、章节标题、版本标签和事件摘要；具体的大纲内容、逐句意图、审阅批注和 AI 回应默认隐藏，只有你勾选的条目才会放进 JSON（旧版格式记录只支持整条披露）。下载前点 **预览审稿人视角**，核对一遍公开的项目名、版本标签、摘要和原文，确认无误再下载。
4. **连同原始 PDF 一起提交并留底。** 把 `paperroom-log.json` 和当时保存的那一份 PDF 一起提交，并自己留一份底稿。重新编译、加水印或经投稿系统重新排版都会改变文件字节，即使肉眼看着一模一样，指纹也会不匹配。

## 审稿人怎么看、怎么验

审稿人可以从自己信任的来源（Paperroom 插件安装包或项目仓库的 `docs/verify.html`，点此查看[验证页](verify.html)）在本地浏览器直接打开验证页——**不用装插件、不用登录、也不会上传任何文件**。

把 `paperroom-log.json` 拖进去就能直接阅读时间线，再拖入投稿 PDF 就能核对稿件。顶部的三项结果各自回答一个独立问题：

| 校验项 | 它能帮你确认什么 |
| --- | --- |
| **日志一致** | 验证页会重算所有公开事件和已公开原文的指纹，并检查先后顺序。哪怕没有第三方时间戳，也能确认这份日志内部未被篡改或删减。 |
| **时间戳有效** | 第三方可信机构证明，被覆盖范围内的记录最迟在签发时刻就已存在。页面会标明连续覆盖到第几条；如果封存之后又提交了新审阅，后续条目的覆盖状态会单独显示。 |
| **投稿 PDF 匹配** | 核对拖入的 PDF 与该版本保存时的字节是否完全一致。PDF 指纹一致，再配合该版本是否已有可信时间戳覆盖，就能判断“稿件对不对”以及“这版稿件最迟何时存在”。只拖日志时，此处显示「尚未核对 PDF」。 |

如果日志里混有隐藏了原文的旧格式记录，那一条无法重算摘要，页面会明确标出限制。若日志由自建时间戳机构签发，审稿人可以在验证页载入自己信任的 CA 证书，或者在解压后的插件目录里用命令行离线复核：

```sh
python3 scripts/verify_timestamps.py paperroom-log.json --pdf submission.pdf
```

使用自定义机构时加上 `--ca-file trusted-ca.pem`；只核验日志和时间戳时可以省略 `--pdf`。

## 向读者说明证明边界

- **半路接入**：记录只从启用 Paperroom 之后开始。如果论文写到一半才接入，接入前的已有正文只是起点，日志只反映之后的修改过程，绝不补造之前的历史。
- **清理与回滚**：本地清理旧 PDF 或重新顺延 V1、V2 显示编号后，旧稿依然能通过稳定版本 ID 和 PDF 指纹核对。从项目存档恢复后，后续记录会接在恢复的那份历史之后；如需独立复核之前已提交的版本，留好当时提交的日志和 PDF 即可。
- **诚实边界**：日志和 [RFC 3161 时间戳](https://www.rfc-editor.org/rfc/rfc3161) 只证明**记录的完整性与最迟存在时间**；操作者的真实身份、实际思考时长和“人类贡献百分比”，都无法由此得出。
